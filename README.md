# Сервис форм

Менеджер сам собирает форму отклика в админке и публикует её по ссылке, студент заполняет форму, менеджер смотрит ответы — без участия разработчиков.

## Запуск

Требуется Node.js 20+. Из корня репозитория:

```bash
npm install
npm start
```

- Админка: <http://localhost:3000/admin> (без авторизации)
- Публичная форма: ссылка вида `http://localhost:3000/f/<код>` — копируется в админке
- Порт: переменная `PORT`, например `PORT=8080 npm start`
- Тесты (необязательно): `npm test`

Внешних зависимостей нет — только встроенные модули Node.js. Данные лежат в `data/db.json` (создаётся автоматически; чтобы начать с чистого листа, достаточно удалить папку `data`; путь можно сменить через `DATA_DIR`).

## Что умеет

**Менеджер (админка)**
- Конструктор формы: название, описание, вопросы 9 типов (короткий и длинный ответ, email, телефон, число, дата, выпадающий список, один вариант, несколько вариантов), обязательность, порядок вопросов.
- Публикация и снятие с публикации, уникальная ссылка, копирование в один клик.
- Просмотр ответов в таблице, выгрузка в CSV (открывается в Excel, есть защита от formula injection).
- **Аналитика «где бросают форму»** — ответ на вторую проблему из задания: сколько человек открыли форму, начали заполнять, отправили, и по каждому вопросу — сколько дошли до него и сколько ушли именно на нём.

**Студент**
- Открывает ссылку, заполняет форму, получает понятные ошибки у конкретных полей и экран «Спасибо».
- Неопубликованная или удалённая форма показывает страницу «Форма недоступна».

## Принятые решения

- **Хранилище — JSON-файл**, а не SQLite: `npm install` и `npm start` гарантированно работают на любой машине, без нативной сборки и без привязки к версии Node. Запись атомарная (временный файл + rename). Для MVP этого достаточно; при росте нагрузки логично перейти на SQLite/PostgreSQL.
- **Без фреймворков.** Сервер — `node:http`, клиент — ванильный JS. Меньше зависимостей, быстрее старт, нечего ломать.
- **Валидация дважды:** на клиенте для удобства, на сервере для надёжности (типы, обязательность, допустимые варианты, лимиты длины).
- **Защита от XSS:** пользовательский текст попадает в DOM только как текстовые узлы; плюс заголовок `Content-Security-Policy: default-src 'self'`.
- **Редактирование формы не ломает старые ответы:** каждый ответ хранит текст вопроса на момент отправки; удалённые вопросы остаются в таблице ответов колонкой с пометкой «(удалён)».
- **Аналитика анонимна:** на странице формы создаётся случайный идентификатор сессии (в `sessionStorage`), персональные данные для неё не используются. «Ушли здесь» — люди, начавшие заполнять форму, но не отправившие её, чей последний открытый вопрос — этот.

## Что сознательно не делалось

Авторизация в админке (по условию её нет), загрузка файлов, условная логика вопросов, уведомления менеджеру, дублирование форм, пагинация ответов. Первые шаги после MVP: авторизация (иначе любой, кто знает адрес `/admin`, видит ответы) и уведомления о новых откликах.

```

test/smoke.test.js  сквозной тест сценария MVP
data/db.json        данные (создаётся при первом запуске, в git не попадает)
AI_LOG.md           лог работы с AI-инструментами
```
